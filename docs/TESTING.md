# Матрица проверки VirtualKVM 0.3.0

Этот документ разделяет автоматические проверки кода, локальные синтетические сценарии и ручные проверки на Windows/macOS. Успех одного уровня не доказывает остальные. Таблица ниже описывает обязательные сценарии; статус конкретной сборки определяется её фактическими результатами, а не наличием сценария в таблице.

## Воспроизводимый запуск

Установите зависимости из `requirements.lock`, приложение и FFmpeg, как описано в README. В активированном окружении:

```bash
python -m virtualkvm doctor
python -m unittest discover -s tests -v
python -m virtualkvm smoke --fps 240
python -m virtualkvm smoke --fps 240 --audio
```

Для машины без экрана установите `QT_QPA_PLATFORM=offscreen`. Это позволяет проверять GUI-логику; реальный экран, аудиовыход и разрешения ОС этот режим не создаёт.

Ключ `--audio` включает приём A/V через QtMultimedia с выключенным аудиовыходом. Он проверяет путь проигрывателя и видеосинк, а не звучание колонок. Отдельные media-тесты проверяют реальные H.264/AAC и HEVC/AAC-потоки через зашифрованный SRT и локальный MPEG-TS-релей: кодеки и стерео 48 кГц, нечётный viewport 321×181 с coded-размером 322×182, монотонность PTS и согласованность начала/конца дорожек. Пороги этого короткого теста — 100 мс в начале и 150 мс в конце примерно секундного фрагмента; они не являются измерением акустической задержки или длительного drift.

В безэкранном Linux CLI выбирает `QT_QPA_PLATFORM=offscreen` и `QT_AUDIO_BACKEND=pulseaudio`, если значения не заданы. Это обходит недоступную конфигурацию PipeWire на тестовом стенде. Для самостоятельного запуска GUI-тестов в такой среде задайте их до импорта Qt. Не переносите Linux-настройку аудиобэкенда на Windows/macOS.

Для отдельной области можно использовать discovery с шаблоном, например:

```bash
python -m unittest discover -s tests -p "test_control.py" -v
python -m unittest discover -s tests -p "test_media.py" -v
```

Имена дополнительных тестовых файлов смотрите в текущем каталоге `tests`. Сохраняйте полный результат и код завершения. Различайте успешные, упавшие, пропущенные и не запущенные проверки. Нулевое количество тестов не подтверждает готовность.

## Автоматические сценарии

| Область | Что проверять | Критерий |
| --- | --- | --- |
| Зависимости | FFmpeg, SRT, кодеры, QtMultimedia, платформенные возможности | Явный успех или понятная ошибка конкретной отсутствующей возможности |
| TLS и идентичность | Корректный и неверный SHA-256-отпечаток | Сессия устанавливается только после совпадения доверенного отпечатка |
| Pairing | Верный/неверный PIN, повторы, ограничения попыток, неполный обмен | Непрошедшая аутентификацию сторона не получает управление, файлы или ключи потока |
| LAN-поиск | Реальные mDNS-узлы на loopback, разбор TXT, удаление хоста, выбор адреса LAN вместо VPN | Взаимное обнаружение; неверные данные отклоняются, PIN не публикуется |
| Подтверждение | Совпадение TLS-кода, разные коды новых соединений, отказ каждой стороны, отмена ожидающего запроса | Без подтверждения нет захвата; отмена очищает ожидание |
| Права владельца | Только просмотр, ввод, файлы, clipboard и звук | Запрет проверяется на хосте, а не только кнопками GUI |
| TCP-видео | Два реальных TLS-потока, ввод и A/V; неправильный и повторный медиаключ | Кадры и звук приходят, ключ не переиспользуется; отказ медиаканала не выдаёт управление |
| Нет изображения | Успешное управление без кадров | Окна видны сразу, через 20 с показана причина и выполняется отключение |
| Протокол | Неверные типы, слишком большие/обрезанные JSON-фреймы, неизвестные команды | Ограниченный отказ, без зависания и исполнения сообщения |
| Управление | Нажатия/отпускания, координаты двух экранов, колесо, release-all | Нормализованные события маршрутизируются и проверяются; Linux использует dry-run |
| Обрыв связи | Обычное отключение, пропавший сокет, heartbeat timeout, повторное подключение | Удерживаемый ввод освобождается, старые потоки закрываются, новая сессия работоспособна |
| Буфер обмена | Unicode-текст в обе стороны, ограничение размера, выключенный opt-in | Точное содержимое; GUI не применяет текст без разрешения и не зацикливает эхо |
| Обычная передача файла | Непустой/пустой файл, размер, SHA-256, конфликт имени, обрыв | Готовый файл совпадает с исходным; существующий не перезаписывается, временный очищается |
| Общая папка | Выключена, read-only, разрешённая запись, вложенные каталоги | Чтение/скачивание разрешены только после подключения; запись и mkdir только по opt-in |
| Защита общей папки | `..`, абсолютный путь, обратные слеши, ссылки/reparse/hard links, специальные файлы, каталог идентичности | Нет выхода за корень, утечки ключей и записи через ссылки |
| Ограничения обмена | 1 ГиБ на файл, блок 64 КиБ, каталог 2048 элементов, параллельная передача | Превышения отклоняются; нельзя исчерпать память неограниченным сообщением |
| Видео H.264 | Синтетический источник → зашифрованный SRT → декодер | Приходят кадры правильного размера; ошибки отправителя/приёмника видны |
| Видео HEVC | Доступность libx265/аппаратного кодера, конфигурация и синтетический путь | Успех поддерживаемого режима или явный отказ отсутствующего кодера |
| Несколько экранов | Три реальных зашифрованных потока с разными ID, портретный источник, маршрутизация указателя | После discovery и подключения источники не смешиваются, ввод достигает нужного экрана, отключение очищает все потоки |
| Конфигурация экранов | 1–8 источников, >8/дубликаты/неверные типы, legacy host без capabilities | Восемь потоков согласуются; неверная схема отклоняется; старый хост получает совместимые параметры |
| Схема и назначения | Перетаскивание Qt-мышью, клавиатура, X/Y, отрицательные координаты, fullscreen/local QScreen | Применение сохраняет схему, отмена её не меняет; настройки хоста остаются прежними |
| Портрет и Retina | Логические координаты, повёрнутые pixel dimensions, сохранение пропорций | Ориентация потока правильная; координаты ввода остаются в системе хоста |
| Произвольный размер | Нечётный размер, собственный размер, разрешение источника | Нечётный край дополнен, RGB обрезан к исходному viewport; лимиты проверены |
| Границы конфигурации | Размеры 1–16384, площадь coded frame 67 108 864, FPS 1–240, битрейт 1–500 Мбит/с | Выход за диапазон отклоняется до создания дорогого процесса |
| Аудио и контейнер | Синтетический sine/AAC вместе с видео, наличие аудио- и видеодорожек | Обе дорожки присутствуют в принимаемом MPEG-TS с временными метками |
| A/V-релей | Сохранение PTS при remux, локальный HTTP, старт/закрытие | Проигрыватель получает совместимый поток; нет зависшего сервера после остановки |
| Qt A/V | Один QMediaPlayer, QAudioOutput и видеовывод; ошибка backend/device | Общая шкала воспроизведения; проблема аудиоустройства видна, а не маскируется |
| GUI | Русские подписи, профили, собственные настройки, DPI, два окна, fullscreen | Настройки применяются; обработчики не блокируют GUI поток |
| GUI-ввод | Потеря фокуса, аварийная комбинация, переполнение/обрыв очереди | Отключение управления и отпускание всех удерживаемых клавиш/кнопок |
| GUI-предпочтения | Сохранение профиля, схемы, миграция старых двух экранов и пути к общей папке | Секреты, PIN и доверенный fingerprint не попадают в обычный файл настроек |
| Сборка | PyInstaller на текущей ОС, launcher, лицензии, запуск doctor/ui-check/smoke | Исполняемый файл запускается с отдельно установленным FFmpeg |

Сценарий `smoke` проверяет интеграцию, но его счётчик декодированных кадров не равен физической частоте монитора. Метаданные 240 FPS и даже достаточная скорость генератора не доказывают захват/показ двух 4K-экранов при 240 FPS. Для строгой проверки целостности конечного клипа сравнивайте количество кадров и хеши; для живого просмотра отдельно учитывайте допустимый отброс устаревших кадров в ограниченной очереди.

## Проверка пакета

Собирайте пакет на соответствующей ОС:

```bash
python -m pip install -e ".[build]"
python scripts/package.py --console
```

Для Linux/Windows каталожная сборка находится в `dist/VirtualKVM`; на macOS GUI-сборка также создаёт `.app`. Запустите её `doctor`, `ui-check`, `smoke --fps 240` и `smoke --fps 240 --audio` из терминала. Затем проверьте GUI без консоли и запуск на отдельной чистой машине с установленным FFmpeg. Убедитесь в наличии каталога `licenses` в ресурсах.

В macOS-пакете должны присутствовать purpose strings для экрана, микрофона и ввода в `Info.plist`. Они вносятся до создания/запечатывания bundle. Сам факт наличия строк не доказывает наличие TCC-разрешений или подписи для распространения. Подпись разработчика и нотарификация в локальную сборку не входят.

CI настроен на Linux/Windows/macOS и выгрузку артефактов. **Удалённый CI и нативные пакеты Windows/macOS нельзя считать проверенными, пока соответствующие задания действительно не завершились.** Мок-тест WinAPI на Linux не равен проверке WinAPI на Windows.

`discovery-check` проверяет два настоящих mDNS-узла на loopback, включая расширения zeroconf в установленной сборке. Это не проверка прохождения multicast между физическими ПК; она включена в каждый нативный установочный сценарий.

`ui-check` открывает и закрывает установленный интерфейс с временными настройками и проверяет SVG-ресурс. Эта проверка также входит в нативную проверку каждого установщика перед выпуском.

## Ручная матрица Windows ↔ macOS

До испытаний запишите модели CPU/GPU, версии ОС/драйверов/FFmpeg, мониторные режимы, тип сети и выбранный кодер. Меняйте один параметр за раз.

| Сценарий | Порядок | Что зафиксировать |
| --- | --- | --- |
| Windows → Mac | Windows как хост, один 1080p-экран, сначала 60 FPS, затем желаемые 240 FPS | Запуск захвата, фактические кадры, ошибки FFmpeg, нагрузка, задержка |
| Mac → Windows | Поменять роли, выдать Screen Recording и Accessibility | Выбранный AVFoundation-экран, отсутствие перепутанного монитора, фактическая частота |
| Несколько мониторов | Два и более источника, смешанные размеры/DPI, портрет; окна по схеме и назначения отдельным локальным мониторам | Физическое размещение/fullscreen, углы указателя, отрицательные координаты, отсутствие растяжения; отключение локального монитора |
| Разрешение источника | Мониторы хоста и клиента разных размеров | Каждый поток использует нужный размер источника; физический видеорежим ОС не меняется |
| Свой размер | Чётный и нечётный viewport; затем 4K и только поддерживаемые большие режимы | Масштаб, один пиксель padding при A/V, отсутствие повреждений; явный отказ кодера при лимите |
| Аппаратный H.264/HEVC | NVENC/QSV/AMF на Windows, VideoToolbox на Mac | Действительно используемый кодер; отсутствие скрытого software fallback |
| Два 4K/240 FPS | Только на подходящих GPU/мониторах; постепенно повысить нагрузку | Достигнутая частота каждого этапа, потери, битрейт, температура; непройденная цель остаётся непройденной |
| Обычный ввод | Клавиши, модификаторы, drag, прокрутка, разные раскладки | Предсказуемые клавиши хоста; Ctrl и Command не подменяются автоматически |
| Аварийный выход | Удерживать клавишу, нажать Ctrl+Alt+Shift+Escape; сменить фокус; отключить сеть | Нет залипших клавиш после каждого случая, управление возвращается локально |
| Clipboard/files | Unicode, переключение opt-in, конфликт имён, отмена передачи | Точное содержимое, отсутствие утечки при выключенной функции, очистка временных файлов |
| Общая папка | Только чтение → разрешённая запись → выключение → переподключение | Права в браузере совпадают с хостом; нельзя скачать/загрузить за пределами корня |
| Системный звук Windows | Выбрать Stereo Mix/подготовленный виртуальный кабель | Передаётся нужный вывод приложений, а не случайный микрофон; локальный звук маршрутизирован намеренно |
| Системный звук macOS | Подготовить BlackHole/иной loopback, выбрать его индекс | Передаётся выбранный системный звук; разрешения и выбор устройства сохраняют ожидаемое поведение |
| Два окна и звук | Включить audio для первого экрана | Нет двойного воспроизведения/эха; закрытие/переподключение не оставляет звук |
| A/V-синхронизация | Передать ролик с одновременной визуальной вспышкой и звуковым импульсом | Рассогласование при старте и через 10/30/60 минут; отсутствие нарастающего drift |
| Рестарт и отказы | Перезапуск хоста, смена аудиоустройства, потеря сети, сон/пробуждение | Понятное состояние, освобождённый ввод, очищенные процессы, работающее переподключение |
| Разрешения и защищённые экраны | Отказать TCC/микрофону; проверить UAC без попытки обхода | Понятный отказ и отсутствие ложного сообщения об успешном захвате/вводе |

Для измерения сквозной задержки используйте внешний высокочастотный видеозаписывающий прибор, одновременно видящий источник и клиент, либо сопоставимую проверенную методику. Разница между счётчиками/таймерами разных компьютеров без синхронизации часов не является корректной оценкой задержки. Для A/V нужно отдельно учитывать задержки акустического выхода и записи измерительного устройства.

## Границы текущих доказательств

В облачной Linux-машине доступны синтетические источники, loopback-сеть, программные кодеры, логика Qt в offscreen-режиме и локальная Linux-сборка. Нативные Windows/macOS SDK/API, разрешения TCC, реальный звук/экраны, драйверы GPU, Ethernet между двумя устройствами и физические мониторы здесь отсутствуют. Поэтому соответствующие строки ручной матрицы остаются **не выполненными на этом стенде**, даже если весь автоматический suite завершился успешно.

Перед выдачей версии пользователю фиксируйте точный коммит/снимок исходников, команды, количество выполненных тестов и явные результаты. Не переносите результат старой сборки на обновлённый пакет без повторной сборки и затронутых проверок.
