# Принципы удалённого управления

В 0.3.0 реализован локальный доступ между открытыми приложениями. По последнему запросу пользователя Интернет-сервер и NAT traversal отложены. Сервер RustDesk, его протокол, ID и учётные записи не используются.

Изучены общие решения RustDesk: независимые управление и медиаданные, явное подтверждение владельца, отдельные права сеанса, варианты прямого/relay-подключения. Для VirtualKVM выбраны LAN/mDNS, собственный сценарий двусторонней сверки короткого кода и отдельные TLS-каналы с одноразовыми ключами. Разные разрешения и приложения в ОС обслуживает существующий конвейер VirtualKVM.

Код RustDesk, protobuf-схемы, библиотеки и ресурсы не перенесены. Самостоятельная реализация VirtualKVM остаётся под MIT. Сторонние runtime-зависимости перечислены в THIRD_PARTY_NOTICES.md.

Источники архитектурного сравнения — RustDesk, коммит `0d6265bb26b8127061ea14c7a5e5c602ddec8778`:

- [Обзор структуры и self-hosted rendezvous/relay](https://github.com/rustdesk/rustdesk/blob/0d6265bb26b8127061ea14c7a5e5c602ddec8778/README.md).
- [Жизненный цикл сеанса и отдельные разрешения](https://github.com/rustdesk/rustdesk/blob/0d6265bb26b8127061ea14c7a5e5c602ddec8778/src/server/connection.rs).
- [Разделение подключения и relay](https://github.com/rustdesk/rustdesk/blob/0d6265bb26b8127061ea14c7a5e5c602ddec8778/src/server.rs).
- [AGPL-3.0 upstream](https://github.com/rustdesk/rustdesk/blob/0d6265bb26b8127061ea14c7a5e5c602ddec8778/LICENCE) — относится к RustDesk, чей код не включён в VirtualKVM.

Для будущего Интернет-доступа понадобится отдельно развернуть rendezvous/relay, сохранить проверку конечного устройства и явно определить постоянный доступ. В текущей версии таких возможностей нет.
