# Установщики Windows и macOS

Пакеты содержат VirtualKVM, Python, Qt, FFmpeg и ffprobe. Устанавливать Python, настраивать `PATH` или скачивать компоненты из мастера не нужно.

## Скачать и установить

Готовые пакеты публикуются в [Releases](https://github.com/Suqesse/VirtualKVM/releases). Результат нативной сборки до публикации находится в успешном запуске [Installers → Artifacts](https://github.com/Suqesse/VirtualKVM/actions/workflows/installers.yml).

| Компьютер | Файл | Действие |
| --- | --- | --- |
| Windows x64 | `VirtualKVM-<версия>-windows-x64-setup.exe` | Запустите мастер установки. |
| Mac с Apple Silicon | `VirtualKVM-<версия>-macos-arm64.pkg` | Пройдите стандартный мастер macOS. |
| Mac с Intel | `VirtualKVM-<версия>-macos-x86_64.pkg` | Пройдите стандартный мастер macOS. |
| Mac, любой из двух вариантов | Соответствующий `.dmg` | Перенесите приложение на ярлык Applications. |

Пилотная версия поддерживает Windows x64 и macOS 15 или новее на Apple Silicon / Intel.

Архитектуру Mac можно посмотреть в **Apple → Об этом Mac → Чип / Процессор**. Минимальная macOS вычисляется по фактическим зависимостям приложения и проверяется мастером `.pkg`. Qt зафиксирован на 6.11.3: у бинарников 6.12.0 фактический минимум — macOS 26, а у выбранной версии — не выше macOS 15 для обеих архитектур. [Аудит исходных wheels и SHA-256 →](validation/macos-qt-wheels.json)

Пилотные пакеты не имеют доверенной подписи Microsoft/Apple, если она отдельно не настроена владельцем проекта. SmartScreen или Gatekeeper могут запросить подтверждение запуска. Проверяйте источник и контрольные суммы; установщик не отключает защиту ОС. Сертификаты и аккаунты разработчиков в репозиторий не включены.

## Windows

- Мастер доступен на русском и английском языках.
- По умолчанию установка выполняется без администратора, для текущего пользователя: `%LOCALAPPDATA%\Programs\VirtualKVM`.
- Ярлык появится в меню «Пуск»; ярлык рабочего стола выбирается отдельно.
- Хост не запускается автоматически. Сначала откройте приложение и настройте подключение.

Для обновления запустите новый установщик: постоянный AppId сохраняет путь установки. Удаление: **Параметры → Приложения → Установленные приложения → VirtualKVM → Удалить**. Настройки, идентичность подключения, загрузки и выбранные общие папки сохраняются.

## macOS

`.pkg` и `.dmg` — два способа установить одно приложение; использовать оба не нужно.

- **PKG:** стандартный мастер ставит приложение в `/Applications`; может понадобиться пароль администратора.
- **DMG:** откройте образ, перетащите VirtualKVM в Applications, извлеките образ и запускайте приложение из Applications.

Перед обновлением закройте приложение и установите новую версию тем же способом. Для удаления перенесите приложение в Корзину. Пользовательские данные `~/.virtualkvm` и общие папки остаются.

Разрешения на запись экрана, «Универсальный доступ» и выбранный аудиовход выдаются обычным способом в системных настройках. Пакеты не выдают их автоматически. Для системного звука нужен подходящий источник: Stereo Mix / виртуальный кабель на Windows или loopback-устройство на Mac. [Настройка функций →](GUIDE.md)

## Проверка пакетов

CI использует Windows и macOS runners с программным декодером для воспроизводимых проверок в виртуальной среде и проверяет:

1. Тесты приложения и синтетическое A/V-соединение.
2. FFmpeg/ffprobe с пустым `PATH`: SRT, реальное кодирование H.264/AAC и анализ результата.
3. PyInstaller-пакет с иконкой, версией и встроенным медиарuntime.
4. Компиляцию Inno Setup либо `pkgbuild` / `productbuild` / `hdiutil`.
5. Установку, запуск без внешнего FFmpeg, обновление и сохранение пользовательских данных.
6. Удаление Windows-приложения, содержимое и монтирование Mac `.dmg`.

В CI рядом с пакетами находятся `installation-check.json` и `SHA256SUMS`; в Releases отчёты трёх платформ объединены в `installation-checks.json`. Проверка установщика не подтверждает реальные 4K/240 FPS, ввод на защищённом рабочем столе или физический аудиовыход. [Полная матрица →](TESTING.md)

## Собрать самостоятельно

Сборка выполняется на целевой ОС. Установите зависимости приложения и PyInstaller:

```bash
python -m pip install -r requirements.lock
python -m pip install -e ".[build]"
```

### Windows

Нужен Inno Setup 6. В автономный пакет включаются настоящие бинарники FFmpeg из `ffmpeg-full/tools/.../bin`, а не launcher shims Chocolatey.

```powershell
python scripts/package.py --bundle-ffmpeg --ffmpeg C:\path\to\ffmpeg.exe --ffprobe C:\path\to\ffprobe.exe
python scripts/installer.py
```

### macOS

CI собирает FFmpeg 9.0.2 из официального исходного архива с проверкой SHA-256 и SRT/x264/x265. На Apple Silicon зависимости устанавливаются из Homebrew; на Intel они собираются из закреплённых исходников скриптом `scripts/build_media_deps_macos.sh`, без сборки всего дерева зависимостей Homebrew. Обычная формула `ffmpeg` может не включать SRT; для разработки из готового Homebrew-пакета используйте `ffmpeg-full`.

```bash
bash scripts/build_ffmpeg_macos.sh
python scripts/package.py --bundle-ffmpeg \
  --ffmpeg build/ffmpeg-native/runtime/bin/ffmpeg \
  --ffprobe build/ffmpeg-native/runtime/bin/ffprobe
python scripts/installer.py
```

Результат — `dist/installers`. `MACOS_APP_SIGN_IDENTITY` включает Developer ID при сборке приложения; `MACOS_INSTALLER_SIGN_IDENTITY` — подпись `.pkg`; `MACOS_NOTARY_PROFILE` — отправку через `notarytool` и stapling. Сертификаты и профиль должны уже находиться в keychain. Пароли и приватные ключи не передавайте в исходниках или аргументах команд.

Windows Authenticode выполняется владельцем сертификата отдельно перед распространением. Наличие Inno Setup само по себе не означает наличие подписи.
