# Руководство VirtualKVM

Передача изображения, звука, клавиатуры и мыши между Windows и macOS по локальной сети. На одном компьютере запускается хост — источник изображения и получатель ввода; на другом — клиент, принимающий изображение. Для обратного направления поменяйте роли. Версия 0.1.0 предназначена для пилотного использования и проверки на целевых компьютерах.

Видео H.264 или HEVC и, при включении, звук AAC передаются по SRT с шифрованием AES. Управление использует TLS с проверкой отпечатка сертификата и PIN. Приложение поддерживает отдельные окна для двух экранов, текстовый буфер обмена по выбору пользователя, отправку файлов на хост и браузер явно выбранной общей папки.

**240 FPS — желаемая частота, а не обещание производительности.** Настройка задаёт частоту видеопотока. Реальная частота захвата и отображения зависит от мониторов, API ОС, разрешения, GPU, кодера и сети. Синтетический тест в Linux не подтверждает работу двух 4K-мониторов при 240 FPS или конкретную задержку на Windows/macOS.

## Установка из исходников

Для обычной установки используйте автономные пакеты Windows и macOS: [инструкция](INSTALLERS.md). Описанные ниже Python и FFmpeg нужны при запуске из исходников.

Нужны Python 3.11 или новее и FFmpeg с поддержкой SRT, H.264/HEVC, AAC и нужного системного захвата. `ffmpeg` и `ffprobe` должны находиться в `PATH`. Python-зависимости включают PySide6-Essentials и PySide6-Addons для QtMultimedia, cryptography и, на macOS, мост Quartz. Полный метапакет PySide6 с WebEngine не требуется.

- **Windows:** установите Python с python.org и FFmpeg из источника, указанного на [ffmpeg.org/download.html](https://ffmpeg.org/download.html). Например, при установленном Chocolatey: `choco install ffmpeg-full -y`. Откройте новый терминал после установки.
- **macOS:** установите Python и FFmpeg с SRT: `brew install python ffmpeg-full`; при необходимости добавьте `$(brew --prefix ffmpeg-full)/bin` в `PATH`.
- **Linux:** используется для разработки и синтетических проверок. Для Debian/Ubuntu: `sudo apt-get install ffmpeg python3-venv`. Нативный захват и ввод Linux не реализованы.

В каталоге репозитория:

```bash
python -m venv .venv
```

Активация в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация в macOS/Linux:

```bash
source .venv/bin/activate
```

Затем:

```bash
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
python -m virtualkvm doctor
python -m virtualkvm
```

Команда `doctor` помогает проверить FFmpeg и возможности текущей платформы. Не устанавливайте случайные неподписанные сборки FFmpeg и не отключайте проверки загрузок для устранения ошибок установки.

Если FFmpeg установлен вне `PATH`, задайте полный путь переменными `VIRTUALKVM_FFMPEG` и `VIRTUALKVM_FFPROBE` перед запуском. Это также полезно для macOS-приложения, открытого из Finder, где окружение может отличаться от терминала.

## Первое подключение

1. Подключите оба компьютера к одной LAN; для высокой частоты предпочтителен Ethernet. Запустите приложение на обоих компьютерах.
2. На компьютере-источнике откройте раздел хоста и запустите его. При необходимости укажите адрес интерфейса LAN и TCP-порт; стандартный порт управления — **24800**.
3. На втором компьютере откройте раздел подключения. Введите IP-адрес хоста, порт, PIN и полный SHA-256-отпечаток сертификата, показанный на хосте. Сверьте отпечаток непосредственно на доверенном экране хоста или по другому доверенному каналу.
4. Выберите один или два экрана, профиль или собственные параметры. Для первого подключения удобно начать с 1920×1080, затем измерить поведение при желаемых 240 FPS. Если нужен звук, включите его отдельно и выберите подготовленный источник на хосте.
5. Подключитесь. Каждый выбранный экран открывается в своём окне. Разместите окна на физических мониторах; при необходимости включите полноэкранный режим.
6. Включайте передачу ввода только когда готовы управлять хостом. Ввод передаётся из активного окна просмотра. При потере фокуса удерживаемые клавиши и кнопки отпускаются.

**Аварийная клавиша: `Ctrl+Alt+Shift+Escape`.** Она отключает передачу ввода из окна просмотра и отпускает удерживаемые клавиши. Выход из полноэкранного режима также доступен через элементы окна. На macOS клавише Alt соответствует Option.

Ctrl и Meta/Command передаются как разные клавиши; автоматической замены Ctrl ↔ Command нет. Печатные клавиши обрабатываются с учётом раскладки хоста; ввод Unicode-текста, IME и перенос раскладки между ОС не эмулируются.

## Профили, разрешение и кодеки

| Профиль | Размер | Частота | Битрейт одного экрана | Буфер SRT |
| --- | --- | --- | --- | --- |
| Игры · 240 FPS | 1920×1080 | 240 FPS | 45 Мбит/с | 30 мс |
| Работа · 60 FPS | 1920×1080 | 60 FPS | 16 Мбит/с | 60 мс |
| Качество · 4K / 60 FPS | 3840×2160 | 60 FPS | 60 Мбит/с | 60 мс |
| Свой профиль | Вручную | 1–240 FPS | 1–500 Мбит/с | Вручную |

Можно выбрать стандартное, локальное или собственное разрешение. Параметр «Родное разрешение источника» использует размер каждого выбранного экрана хоста. Это важно, если локальные мониторы клиента имеют другое разрешение.

Собственные ширина и высота допускаются от **1 до 16384**. Площадь закодированного кадра ограничена **67 108 864 пикселями**. Для H.264/HEVC нечётный край дополняется до следующего чётного размера справа или снизу. В режиме RGB-просмотра добавленный край обрезается; при A/V-воспроизведении может остаться полоса шириной один пиксель. Возможности конкретного кодера могут быть существенно ниже этих пределов — проверка конфигурации не гарантирует её поддержку GPU.

H.264 — исходный совместимый выбор. HEVC может уменьшить необходимый битрейт, но требует подходящего кодера и декодера. Размер выходного кадра может отличаться от физического экрана: это масштабирование, а не установка виртуального монитора или изменение видеорежима ОС. Неподдерживаемая нативная частота захвата требует другого режима на реальной машине.

Предпочтения интерфейса сохраняются без PIN и доверенного отпечатка. Сохранённый адрес или путь к папке не разрешает новое подключение или запись автоматически: включение общего доступа и согласие на запись не сохраняются как обычные предпочтения. Запрошенная частота и фактические показатели получения/показа кадров отображаются раздельно; последние не являются измерением полной задержки от физического экрана до экрана.

## Звук и синхронизация

«Передавать звук» включается отдельно. Аудио AAC и видео идут в одном транспортном потоке с временными метками. В окне A/V используется QtMultimedia: один `QMediaPlayer` управляет аудио и видео по общей шкале времени. Звук передаётся вместе с первым выбранным экраном, чтобы два окна не воспроизводили его дважды.

Синтетический источник передаёт тестовый синусоидальный тон, а не звук рабочего стола. Автоматическая A/V-проверка воспроизводит его с выключенным звуком.

Для системного звука нужен источник, который ОС предоставляет как записывающее устройство:

- **Windows:** выберите доступный через DirectShow источник Stereo Mix/«Стерео микшер» или виртуальный аудиокабель. Stereo Mix зависит от драйвера. Если установлен виртуальный кабель, направьте звук нужных приложений на его выход и выберите соответствующий записывающий вход в VirtualKVM.
- **macOS:** выберите аудиоустройство AVFoundation. Для системного звука обычно требуется заранее установленное loopback-устройство, например BlackHole. В Audio MIDI Setup можно подготовить многовыходное устройство для одновременного локального прослушивания и передачи через loopback.
- Обычный микрофон также может быть источником, но он не заменяет захват системного звука. Для него требуется разрешение на микрофон.

Внешние аудиодрайверы приложение не устанавливает. Используйте официальные источники, самостоятельно выберите маршрутизацию и убедитесь, что передаётся именно нужный звук. Если источник не указан или недоступен, включение аудио должно завершаться понятной ошибкой, а не незаметно передавать другой микрофон.

На Windows входы захвата используют согласованные временные метки и синхронизацию FFmpeg; на macOS используется общий AVFoundation A/V-вход. На клиенте поток пересылается через локальный HTTP-медиарелей в QtMultimedia с сохранением временных меток. Это механизм синхронизации, а не уже измеренная гарантия допустимого A/V-рассогласования. Реальное воспроизведение через аудиоустройство, устойчивость синхронизации и задержку нужно проверить на целевом оборудовании.

## Разрешения ОС

**macOS:** в «Системные настройки → Конфиденциальность и безопасность» разрешите запись экрана для процесса, выполняющего захват, и «Универсальный доступ» для процесса, внедряющего ввод. Для выбранного аудиовхода может понадобиться разрешение на микрофон. При запуске из исходников это могут быть Python, терминал и/или FFmpeg; при запуске сборки — приложение и внешний FFmpeg. После изменения разрешений может потребоваться перезапуск. Сначала проверьте вывод `doctor` и разрешения на стороне, работающей как хост. Описания разрешений в macOS-пакете не выдают разрешения автоматически.

**Windows:** используйте обычный пользовательский рабочий стол. Экран входа, защищённый рабочий стол UAC и некоторые окна с более высокими привилегиями могут не захватываться или не принимать ввод. Приложение не обходит ограничения ОС.

## Сеть и производительность

- Разрешите входящий **TCP 24800 на хосте** и входящие **UDP-порты видеопотоков на клиенте**. Порты видео согласуются при подключении и могут меняться. На Windows предпочтительно разрешить приложения Python/VirtualKVM и FFmpeg в брандмауэре для частной сети, ограничив доступ локальной подсетью.
- Для первого теста используйте одну подсеть IPv4 без гостевой Wi-Fi-изоляции. Проброс портов маршрутизатора для обычной LAN не нужен.
- SRT требует UDP в обоих направлениях. Открытый TCP-порт управления сам по себе не означает, что видеопоток доступен.
- Значение 240 FPS означает бюджет около **4,17 мс на кадр**. Удвоение числа экранов и увеличение разрешения повышают нагрузку на захват, кодирование, декодирование и отрисовку.
- Режим `auto` проверяет доступность аппаратного кодера и сообщает о переходе на программное кодирование. Наличие названия кодера в FFmpeg не доказывает наличие подходящего GPU.
- Windows может использовать NVENC, QuickSync или AMF; macOS — VideoToolbox. Выбор зависит от установленной сборки FFmpeg и оборудования. Программный H.264 — совместимый вариант для диагностики, но не гарантия 4K/240 FPS.
- Битрейт задаётся для отдельного видеопотока. Настраивайте его вместе с разрешением, частотой и возможностями LAN. Не уменьшайте задержку SRT до значения, при котором появляются повреждённые кадры.

## Буфер обмена и файлы

Синхронизация **текстового** буфера обмена включается явно и по умолчанию выключена. Включите её на тех сторонах, где хотите применять входящий текст. Передавайте только содержимое, которым намерены поделиться.

Файлы отправляются выбранным пользователем действием с клиента на хост. Каталог приёма по умолчанию — `Downloads/VirtualKVM` в домашнем каталоге хоста. Протокол проверяет размер и SHA-256; незавершённая передача не должна появляться как готовый файл. Пути отправителя не используются как пути записи на хосте. Это передача файлов, а не общий диск или автоматическая синхронизация каталогов.

### Общая папка

На хосте включите «Открыть общую папку» и выберите отдельный каталог. Доступ по умолчанию — **только чтение**. Чтобы разрешить загрузку файлов и создание каталогов, явно включите «Разрешить загрузку в папку».

После защищённого подключения откройте на клиенте «Общая папка…». Браузер показывает содержимое выбранного каталога, навигационную цепочку, скачивание и, при разрешённой записи, загрузку и создание папок. Ничего не монтируется в Finder или Проводнике как системный диск.

Ограничения обмена:

- До **1 ГиБ на файл**, блоки до 64 КиБ, проверка размера и SHA-256 в обоих направлениях.
- На Windows скачиваемый исходный файл блокируется от записи, переименования и удаления до завершения, отмены передачи или отключения клиента.
- Готовый файл не перезаписывается молча; выберите новое имя при конфликте. Оборванная передача очищает временный файл.
- До 2048 элементов в ответе просмотра каталога; слишком большой каталог нужно разделить.
- Нельзя выйти за выбранный корень через абсолютный путь, `..` или обратные слеши. Символические ссылки, Windows reparse points, POSIX hard links и специальные файлы не предоставляются.
- Каталог с ключами/идентичностью хоста, его родители и дочерние каталоги нельзя публиковать как общую папку. Выберите отдельный каталог с файлами для обмена.

Доступ к общей папке получает только прошедшая TLS/PIN-подключение сторона. Разрешения общей папки не заменяют файловые разрешения ОС и не создают сетевой SMB/NFS-сервис.

## Запуск без интерфейса и проверка

Синтетический хост генерирует тестовое изображение и использует безопасную имитацию ввода:

```bash
python -m virtualkvm host --bind 127.0.0.1 --port 24800 --synthetic --state-dir ./build/demo-host
```

Хост показывает PIN и отпечаток для подключения. Не публикуйте их в общедоступных логах.

Для обычного хоста источник звука задаётся параметром `--audio-device`, каталог обмена — `--share-dir`; запись в него разрешается отдельным `--share-write`. Каталог должен существовать. Без `--share-dir` общий доступ выключен; без `--share-write` папка доступна только для чтения.

Проверка локальной связки управления и видео:

```bash
python -m virtualkvm smoke --fps 240
```

Дополнительная проверка общей шкалы A/V через QtMultimedia, без звука в колонках:

```bash
python -m virtualkvm smoke --fps 240 --audio
```

Проверки репозитория:

```bash
python -m unittest discover -s tests -v
```

Полная автоматическая проверка с ограничением времени выполнения и JSON-отчётом:

```bash
python scripts/validate.py
# Дополнительно проверить уже собранное приложение:
python scripts/validate.py --packaged dist/VirtualKVM/VirtualKVM
```

Результаты и отдельные журналы сохраняются в `build/validation/`. Проверка со звуком воспроизводит синтетический поток с выключенной громкостью: реальный аудиовыход она не подтверждает. Ручные проверки Windows/macOS описаны в [матрице тестирования](TESTING.md).

Для GUI-проверок на машине без экрана установите `QT_QPA_PLATFORM=offscreen`. Синтетический режим проверяет программный видеотракт и протокол; нативный захват, ввод, реальная задержка и физическая частота дисплеев требуют проверки на соответствующих компьютерах.

Полная матрица проверок и ограничения доказательств: [docs/TESTING.md](TESTING.md).

## Локальная сборка приложения

Собирайте приложение на той ОС и архитектуре, где оно будет запускаться. PyInstaller не является кросс-компилятором.

```bash
python -m pip install -e ".[build]"
python scripts/package.py
```

Результат появляется в `dist`. Для диагностики можно собрать приложение с консолью: `python scripts/package.py --console`.

Для обычной сборки FFmpeg устанавливается отдельно. Для автономного установщика выполните `python scripts/package.py --bundle-ffmpeg`, затем `python scripts/installer.py`; детали — в [инструкции](INSTALLERS.md). Локальная сборка не является подписанным или нотарифицированным релизом. Для распространения Windows/macOS-пакетов нужны отдельные процедуры подписи, проверки разрешений и тестирование на чистой машине. При сборке macOS описания назначения экрана, ввода и микрофона добавляются в `Info.plist` через спецификацию `BUNDLE` до создания пакета; они не являются разрешениями TCC и не заменяют действия пользователя.

CI настроен на проверки и сборку артефактов Linux, Windows и macOS. Наличие файла workflow в репозитории не означает, что удалённые задания уже выполнились; результаты конкретного запуска проверяются отдельно.

## Объём реализации

Приложение работает с существующими экранами. Драйвер виртуального дисплея и системные глобальные горячие клавиши не реализованы. Windows использует захват GDI через FFmpeg `gdigrab`, macOS — AVFoundation: это рабочие совместимые API, но не GPU-конвейер DXGI/ScreenCaptureKit с передачей текстур без копирования. Поэтому предельные разрешение, частоту и задержку нужно измерять на оборудовании.

Переключение входа монитора через DDC/CI предоставлено отдельной функцией `virtualkvm.native.set_monitor_input(display, source)` только для Windows; в интерфейсе автоматического переключения физических входов пока нет. Передача видео от DDC/CI не зависит. Обычная отправка файла идёт от клиента к хосту; браузер общей папки позволяет также скачивать выбранные файлы хоста.

Описание компонентов и протокола: [docs/ARCHITECTURE.md](ARCHITECTURE.md).

Код приложения распространяется по MIT. Qt/PySide6, cryptography/OpenSSL, cffi, PyObjC и FFmpeg имеют собственные лицензии. В локальную сборку включаются MIT-текст приложения, [уведомления о зависимостях](THIRD_PARTY_NOTICES.md) и доступные тексты лицензий установленных Python-дистрибутивов. Конкретные сборки FFmpeg с libx264/libx265 могут быть GPL; автоматическая упаковка этого стороннего бинарника не выполняется.
