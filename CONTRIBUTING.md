# Участие в разработке

VirtualKVM — пилотный настольный KVM для Windows и macOS. Linux используется для синтетических интеграционных проверок. Перед изменениями прочитайте [архитектуру](docs/ARCHITECTURE.md) и [матрицу тестирования](docs/TESTING.md).

## Окружение

Установите Python 3.11+ и FFmpeg с SRT. Создайте виртуальное окружение и активируйте его по [руководству](docs/GUIDE.md#установка-из-исходников).

```bash
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
python -m virtualkvm doctor
```

## Проверки

```bash
python scripts/validate.py
```

Отчёт и журналы появятся в `build/validation/`. На Linux без графической сессии используйте `QT_QPA_PLATFORM=offscreen` и `QT_AUDIO_BACKEND=pulseaudio` для отдельных GUI-тестов. Полный валидатор выставляет их сам.

Изменения сетевого протокола проверяйте через реальное локальное соединение. Для изменений ввода добавляйте проверку освобождения клавиш при сбое; для файлов — целостности, границ выбранной папки и очистки незавершённой передачи. Изменения GUI проверяйте также в небольшом окне.

## Pull request

- Опишите пользовательскую проблему и результат изменения.
- Укажите выполненные проверки и их результаты.
- Для интерфейса добавьте скриншот; для нативного API — ОС и оборудование, на которых проверяли.
- Не записывайте PIN, ключи, сертификаты или личные данные в исходники и журналы.
- Различайте запрошенные FPS, декодирование, показ кадров и измеренную задержку. Синтетическая проверка не подтверждает производительность реальных мониторов.

Большие изменения предварительно обсуждайте в issue. Необходимые для воспроизведения ошибки параметры описаны в шаблоне сообщения о проблеме.
